    概述

    14 分钟等级: 入门

    Claude Code 是 Anthropic 面向软件工程的 智能体 CLI 工具——一个基于终端的交互界面，能够将大语言模型直接连接到你的代码库、Shell 和开发工作流中。本仓库是 Claude Code src/ 目录的 镜像源码快照，于 2026 年 3 月 31 日因 npm 分发包中的 source map 泄露而公开。此处仅出于 教育和安全研究目的 对其进行维护 README.md。

    该代码库体量庞大：包含约 1,900 个 TypeScript 文件，总计超过 512,000 行代码，以 Bun 作为运行时，并使用 React Ink 构建终端 UI README.md。对于首次接触该代码库的开发者而言，本页面将提供一张架构高层地图，涵盖其主要子系统及其连接方式。

    Claude Code 的功能

    从本质上讲，Claude Code 是一个 工具调用智能体循环。你在终端中输入自然语言提示词；Claude Code 会结合项目上下文构建系统提示词，将其发送给 LLM（通常是 Claude），随后进入循环：模型返回文本或 工具调用，工具执行（如编辑文件、运行 Shell 命令、搜索代码等），执行结果再反馈回对话中。此循环会持续进行，直到模型判定任务完成 src/QueryEngine.ts。

    这个看似简单的循环由一系列丰富的子系统支撑——工具执行、权限管控、终端渲染、多智能体协同、IDE 桥接、插件加载等——我们将在下文逐一剖析。

    高层架构

    下图展示了主要子系统及其相互关系。居于核心位置的是 Query Engine，它驱动着 LLM 对话循环。该引擎由 REPL 界面 进行编排，后者是主要的交互层面，在设置管线完成后由 main.tsx 启动。

    核心子系统

    Query Engine

    QueryEngine 是 Claude Code 的心脏 src/QueryEngine.ts。它维护对话消息历史，并实现了 智能体循环：向 LLM 发送消息、接收响应（可能包含工具调用块）、执行相应工具、将结果反馈回去，并不断重复。该引擎负责处理瞬态 API 错误的重试、上下文窗口管理、思考/预算配置，以及通过 AbortController 进行的中止控制。独立的 ask() 函数提供了一种无状态的替代方案，能够为 SDK/智能体模式入口流式传输 SDKMessage 事件 src/QueryEngine.ts。

    工具系统

    Claude 能够调用的每一项能力都被建模为一个 Tool——一个包含输入模式（基于 Zod 校验的 JSON Schema）、权限检查和执行逻辑的独立模块 src/Tool.ts。buildTool() 辅助函数为 isEnabled、isReadOnly 和 isConcurrencySafe 等可选方法填充了合理的默认值 src/Tool.ts。

    工具在 tools.ts 中注册，并根据当前的权限上下文进行过滤。下表展示了主要分类：

    分类示例描述
    文件操作FileReadTool、FileWriteTool、FileEditTool、GlobTool、GrepTool读取、写入、编辑和搜索代码库
    Shell 执行BashTool、PowerShellTool在系统 Shell 中运行命令
    智能体与多智能体AgentTool、TeamCreateTool、SendMessageTool生成子智能体并协调团队
    外部集成MCPTool、LSPTool、WebFetchTool、WebSearchToolMCP 服务器工具、语言服务器协议、Web 访问
    规划与工作流EnterPlanModeTool、ExitPlanModeTool、TodoWriteTool结构化规划与任务管理
    任务调度CronCreateTool、RemoteTriggerTool定时与远程触发器（受特性门控）

    许多工具通过 Bun 的 feature() 标志有条件地引入，从而在构建时实现死代码消除 src/tools.ts。

    命令系统

    斜杠命令（如 /commit、/review、/compact 等）提供了面向用户的操作，这些操作可以是 本地型（完全在终端内运行，如 /diff 或 /theme），也可以是 提示词型（作为上下文提交给 LLM，如 /review）src/commands.ts。命令由内置模块、.claude/skills/ 中的用户自定义技能、内置技能、插件提供的命令以及 MCP 提供的技能组装而成。特性标志控制着诸如 /voice、/proactive、/ultraplan 和 /bridge 等命令 src/commands.ts。

    终端 UI (React Ink)

    Claude Code 使用 React Ink（一个基于终端的 React 渲染器）来渲染其界面。主屏幕是 REPL.tsx，这是一个约 5,000 行的组件，负责管理提示词输入、消息记录、流式响应、权限对话框、工具调用覆盖层、通知提示以及数十个其他交互元素 src/screens/REPL.tsx。组件树包含 src/components/ 中的约 140 个 UI 组件，涵盖了从加载动画、Markdown 渲染到差异视图和权限请求对话框的方方面面 src/components/。

    状态管理

    应用状态集中存储在 AppState 中，这是一个在 AppStateStore.ts 中定义的深度不可变类型 src/state/AppStateStore.ts。它持有活跃的设置、权限上下文、工具定义、命令列表、MCP 连接、任务状态、插件状态、智能体定义等大量信息。一个轻量级的状态存储器结合 useAppState() 和 useSetAppState() Hooks，在整个 React 组件树中提供了响应式访问能力。

    权限模型

    每次工具调用都会经过权限检查。ToolPermissionContext 定义了当前的模式（default、plan、bypassPermissions、auto）以及允许/拒绝/询问规则 src/Tool.ts。useCanUseTool Hook 将工具系统与 UI 连接起来，在需要批准时向用户展示权限请求对话框。在自动模式下，对话记录分类器可以自动批准或拒绝工具调用。在集群/协调器模式下，工作节点通过邮箱系统将权限请求转发给主导节点 src/screens/REPL.tsx。

    上下文管线

    在每次调用 LLM 之前，Claude Code 会从多个来源组装上下文：系统提示词、git 状态与仓库元数据、CLAUDE.md 文件（项目指令）、用户设置、记忆文件以及 MCP 资源 src/context.ts。该上下文在会话期间会被缓存，以避免冗余的文件系统读取。

    特性标志与死代码消除

    一个显著的架构模式是广泛使用 Bun 的 feature() 函数来进行条件导入 src/main.tsx。诸如协调器模式、语音输入、主动模式、智能体触发器和 Web 浏览器工具等模块，都被包裹在特性门控中，这些门控会在 构建时 求解——未激活的代码会从产物中彻底剥离。这使得生产环境构件保持精简，同时允许所有功能在源码树中并存 README.md。

    需要了解的关键模式

    独立的工具模块：src/tools/ 中的每个工具都是一个包含其实现、提示词和测试的独立目录。工具实现通用的 Tool 接口，除此之外彼此独立——添加一项新功能只需创建一个新目录并在 tools.ts 中注册即可。

    受特性门控的代码路径：许多子系统（语音、协调器、主动模式、伙伴精灵等）通过 feature('FEATURE_NAME') 在构建时进行切换。阅读代码时，由 feature() 守卫的 require() 意味着整个模块可能不会包含在所有构建产物中 src/commands.ts。

    缓存式注册表：工具和命令都使用了惰性、缓存的组装函数。getTools() 和 getCommands() 均带有缓存机制，并在每次调用时根据权限上下文和可用性进行过滤，从而确保技能和插件的热重载能够立即生效 src/tools.ts、src/commands.ts。

    异步生成器流式传输：查询引擎和 ask() 函数以异步生成器的形式产出 SDKMessage 事件，使得助手响应、工具调用和进度更新能够实时流式传输到 REPL 和 SDK 消费端 src/QueryEngine.ts。

    在浏览代码库时，请从 main.tsx 开始了解启动流程，然后跳转到 screens/REPL.tsx 查看所有子系统在运行时是如何连接在一起的。QueryEngine 类以及 tools.ts/commands.ts 注册表是接下来顺理成章的切入点。
