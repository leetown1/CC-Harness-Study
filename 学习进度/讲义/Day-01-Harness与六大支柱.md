## 一句话讲清 Harness

**Harness Engineering = 让"聪明但不可预测"的模型在工程约束下稳定工作的方法论。**

核心哲学八个字：**人类掌舵，Agent 执行**。

模型是引擎，Harness 是缰绳、护栏和高速公路——把模型的不确定性关在可控的工程系统里。

---

## 一个公式 · 95/5

```
Agent = Model + Harness
```

- **Model（5%）**：调用 LLM 本身的代码（构造请求、解析响应）
- **Harness（95%）**：围绕模型的所有工程基础设施——错误恢复、权限管理、上下文压缩、启动性能、工具系统、命令系统、会话持久化……

> **反直觉点**：大多数团队做 AI Agent 把 90% 精力花在调 prompt / 选模型，但真正决定 Agent **可靠、可用、好用** 的，是那 95% 的"非模型"代码。

**记住这句话就够了**：
> AI Agent 的瓶颈从来不在模型智能，而在基础设施。

---

## 六大支柱 · 速查

CC 把这套工程方法论提炼成 6 个支柱。每个支柱对应源码中一个庞大的子系统。

| # | 支柱 | 一句话 | 反直觉点 |
|---|------|--------|----------|
| 1 | **上下文架构** | 精准设计进入模型的信息 | 上下文利用率 > 40% 时模型推理质量显著下滑——所以要 4 级压缩 |
| 2 | **架构约束** | 用代码强制规则，不用 prompt 软约束 | 工具默认走最受限路径，忘了设置 = 走最严 |
| 3 | **自验证循环** | 流程内置验证检查点 | query() 16 步循环里**只有 1 步**在调模型，其余 15 步全在验证 |
| 4 | **上下文隔离** | 多 Agent 协作时上下文要纯净 | 进程级隔离 + 控制面/数据面分离 |
| 5 | **熵治理** | 对抗系统状态自然熵增 | AutoDream 让 AI "做梦"——模拟 REM 睡眠整理记忆 |
| 6 | **可拆解性** | 模块化让 Harness 跟模型迭代解耦 | Skills 用纯 Markdown 定义，非程序员也能扩展 |

下面展开讲每根支柱的"为什么 + 怎么做"。

---

## 支柱 1 · 上下文架构（Context Architecture）

**核心判断**：永远不要让上下文窗口变成垃圾场。

**为什么重要**：研究显示，模型上下文窗口利用率超过 40% 后，推理质量显著下滑。这就是为什么 CC 投入了**不成比例**的工程量在上下文压缩上。

**怎么做**（4 级压缩管道）：
1. **Snip Compact**（最轻量）——移除"僵尸消息"：被后续消息覆盖、已经不再相关的历史内容
2. **Micro Compact**（细粒度）——局部压缩，**保留 prompt cache 连续性**（这是关键——不能破坏缓存）
3. **Context Collapse**（读时投影）——把已归档消息替换成摘要视图，类似数据库的"物化视图"
4. **Auto Compact**（最重量级）——token 超阈值时**调 LLM 自己做全量摘要**

**顺序至关重要**：Snip → Micro → Collapse → Auto。**先便宜后贵**——collapse 能搞定就别动 autocompact，能保留更细粒度的上下文。

> 💡 配套源码：`src/services/compact/` 整个目录 11 个文件，专门干这事。

---

## 支柱 2 · 架构约束（Architecture Constraints）

**核心判断**：用代码强制执行规则，prompt 是建议，代码是法律。

**Fail-Closed 信仰**（CC 的核心安全哲学）：

传统 API 设计里，工具忘了声明权限限制，默认"允许"（Fail-Open）。但在 AI Agent 场景下这是**灾难**——Agent 会探索人类不会触的边界（读 `/etc/shadow`、跑 `rm -rf /`、在 curl 输出里塞 prompt injection）。

CC 的 `buildTool()` 工厂默认值是反过来的：

```typescript
const TOOL_DEFAULTS = {
  isEnabled: () => true,
  isConcurrencySafe: () => false,    // 默认不可并发
  isReadOnly: () => false,           // 默认非只读
  isDestructive: () => false,        // 默认非破坏性
  checkPermissions: (input, ctx) => Promise.resolve({ behavior: 'allow', input }),
  toAutoClassifierInput: () => '',   // 安全分类器默认忽略
}
```

- 安全分类器默认返回空串 → 分类器不参与决策 → 走完整的人工确认流程
- 忘了设置 = 走最受限路径
- **遗漏不是漏洞，是额外的安全层**

> 💡 配套源码：`src/Tool.ts` 第 ~20 行 `TOOL_DEFAULTS`，20 行代码定义了整个安全基线。

## 支柱 3 · 自验证循环（Self-Verification Loops）

**核心判断**：在执行流程中**内置**验证检查点，防止死循环和静默失败。

**最反直觉的事实**：
`query()` 的 while(true) 循环有 16 个步骤，其中**只有 1 步**是调用 LLM API。

其余 15 步全在干这些事：
- 消息准备
- 上下文压缩（4 级）
- 权限验证
- 工具执行
- 结果处理
- 错误恢复
- 状态持久化
- Token 预算检查
- ……

**这就是为什么 `query.ts` 有 1729 行**——真正的"智能"只占几十行，剩余 95% 的代码都在管理这个智能的边界条件。

> 💡 Agent 工程最反直觉的真相：**模型调用是整个系统中最简单的部分**。

---

## 支柱 4 · 上下文隔离（Context Isolation）

**核心判断**：多 Agent 协作时，每个 Agent 的上下文要纯净，防止跨边界信息污染。

**怎么做**：
- **进程级隔离**——子 Agent 有独立的上下文和工具白名单
- **通信接口化**——Agent 之间必须通过结构化消息接口通信，不能共享内存
- **控制面 vs 数据面分离**——Coordinator（决策/调度）看到全局上下文，Worker Agent（执行）看到被裁剪的上下文

> 类比：就像 Unix 进程隔离——每个 Agent 有自己的地址空间，通信走 IPC。

> 💡 配套源码：`src/tools/AgentTool/`。

---

## 支柱 5 · 熵治理（Entropy Governance）

**核心判断**：系统状态会自然熵增——Agent 用得越久，记忆越碎片、越重复、越过时。要主动对抗。

**怎么做 · AutoDream 梦境系统**：

后台跑一个 DreamTask，**不需要用户触发**，目的：整合和沉淀跨会话的知识。

| 阶段 | 名字 | 干什么 |
|------|------|--------|
| Phase 1 | Orient（定位） | 读记忆索引，看清当前知识结构全貌 |
| Phase 2 | Gather（收集） | 收近期会话的新知识、新经验 |
| Phase 3 | Consolidate（整合） | 新旧知识融合，更新记忆文件 |
| Phase 4 | Prune & Index（修剪 + 重建索引） | 删冗余，重建索引 |

灵感来自人类 **REM 睡眠**的记忆巩固机制。

**为什么是"做梦"**？
- 手动整理用户不会做（懒）
- 自动整理需要认知能力（只有 LLM 能做）
- 让 Agent 空闲时自己整理——把问题从用户转移到系统，**最优解**

> 💡 配套源码：`docs/architecture/deep-dive/memory-system.md`。

## 支柱 6 · 可拆解性（Disassemblability）

**核心判断**：模块化设计使 Harness 能跟模型迭代**解耦**——模型升级、Harness 不用动。

**怎么做 · 三个杠杆**：
1. **依赖注入**——每个组件可替换，核心循环可单测（不用起网络、不用读文件）
2. **Skills = Markdown**——技能文件是纯 `.md` + frontmatter，非程序员也能扩展
3. **MCP 标准协议**——工具生态独立于产品迭代，模型降级容错（换供应商不会让系统崩溃）

**Skill 文件长这样**：
```yaml
---
name: my-skill
description: 做什么
when_to_use: 什么时候触发
allowed-tools: Bash, FileRead
model: claude-sonnet-4-20250514
effort: high
---
这里是发给模型的 prompt 内容...
```

为什么是 Markdown？技能本质是"有结构的自然语言"——人类可读可写，frontmatter 给结构化，正文自由自然语言。**不需要编译，不需要 SDK，不需要懂 TypeScript**。

> 💡 配套源码：`src/skills/`。

## 六大支柱 · 互相关系

```
        ┌─ ① 上下文架构 ─┐
        │               │
 ④ 隔离 ┼── ② 约束 ─ ③ 验证 ──┼ ⑤ 熵治理
        │               │
        └─ ⑥ 可拆解性 ─┘
```

- **① + ③ + ④** 管"模型输入"——送什么进去、怎么验证、怎么隔离
- **②** 管"系统边界"——代码层面的强制约束
- **⑤** 管"长期健康"——对抗熵增
- **⑥** 是底座——让前面 5 个都能换实现

**一个比喻**：
- ① 上下文架构 = 餐厅的菜单设计
- ② 架构约束 = 厨房的食品安全规范
- ③ 自验证循环 = 厨师的试吃环节
- ④ 上下文隔离 = 前后厨分离
- ⑤ 熵治理 = 每日清洁 + 月度大扫除
- ⑥ 可拆解性 = 厨房模块化设计（新厨子来了也能上手）

---

## 今日关键 takeaway

1. **公式**：`Agent = Model + Harness`（5% vs 95%）
2. **95% 精力在 Harness**——基础设施决定体验
3. **Fail-Closed**——忘了设置 = 走最严路径
4. **16 步循环只 1 步调模型**——验证比智能更重要
5. **六大支柱互相支撑**——不是并列清单，是一个有层次的方法论
