# Anthropic 五种 Workflow 模式

## 一句话定义
Anthropic 将成功的 Agent 系统归纳为五种可组合的 Workflow 模式，按复杂度递增排列，核心建议是"简单优先"。

## 五种模式

### 1. Prompt Chaining（链式调用）
把任务拆成固定的步骤，串行执行。上一步的输出 = 下一步的输入。
- 适用场景：子任务固定、可以用延迟换准确率的场景
- 例子：用户需求 → 技术规格 → 代码生成 → 代码审查

### 2. Routing（路由）
先分类输入，再分流给对应的专业处理链。
- 适用场景：输入类别明确、不同类别需要不同处理方式
- 例子：客服系统判断"退款/物流/技术问题"→ 走不同处理流程

### 3. Parallelization（并行化）
多个 LLM 同时工作，最后合并结果。两种玩法：
- **分段（Sectioning）**：拆成独立子任务并行处理
- **投票（Voting）**：同一任务让多个 LLM 各自做一遍，取最优
- 适用场景：子任务之间相互独立，或需要多视角验证

### 4. Orchestrator-Workers（编排者 + 工人）
一个"指挥官" LLM 动态拆解任务，分配给多个"工人" LLM 执行，最后综合结果。
- 和 Prompt Chaining 的关键区别：子任务**不是预定义的**，而是动态决定的
- 适用场景：开放式任务，无法提前预知需要哪些子步骤
- 例子：老板说"看看上季度业绩为什么下滑"——指挥官自己决定先查什么、再分析什么

### 5. Evaluator-Optimizer（评估 + 优化）
一个 LLM 生成内容，另一个评估并给反馈，生成者根据反馈改进，循环直到达标。
- 本质："写 → 审 → 改 → 再审"的迭代环
- 适用场景：输出质量可以通过迭代改进、且有明确评估标准

## 设计原则
1. **简单优先**：从最简单的模式开始，只在确实需要时才增加复杂度
2. **透明性**：明确展示 Agent 的规划步骤
3. **ACI 设计**：精心设计 Agent-Computer Interface（工具文档和测试）

## 我的理解
（用户原话）数据分析有固定方法时用 Workflow；老板问开放式问题时用 Agent（Orchestrator-Workers）。
